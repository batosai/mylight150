# mylight150

A service that reads the **mylight virtual battery** percentage from the Android
app and exposes it over HTTP. It lets other tools access this value without
manually opening the app on the phone.

The project uses AdonisJS 7, TypeScript, Redis, and Android Debug Bridge (ADB).
UIAutomator reads the accessible text of the “Batterie virtuelle” section in the
Android interface, without screenshots or OCR.

## How it works

Every five minutes, the `RefreshBattery` job:

1. Acquires a Redis lock to reserve access to the phone.
2. Wakes the phone and opens the mylight app.
3. Checks the session and attempts to sign in again if needed.
4. Refreshes the screen and reads the virtual battery percentage.
5. Stores the value in Redis under the `mylight150_capacity` key.
6. Closes the app, puts the phone to sleep, and releases the lock.

Only integer percentages between 0 and 100 are accepted. If the phone is
unavailable or the reading fails, the last stored value is preserved. Manual
commands use the same lock to avoid interacting with the phone during a reading.

## Requirements

- Node.js, using the version specified in `package.json` to match the project environment.
- npm and a Redis server accessible from the application.
- ADB installed on the machine running the jobs.
- An Android phone with mylight installed, USB debugging enabled, and the machine authorized to use ADB.
- A screen that ADB commands can unlock without entering a PIN.

The automation depends on the Android app’s screens and coordinates. The
documented flow was verified on a Pixel 6a with mylight 1.30.1 and the Jelly
browser. A different phone or changes to the interface may require adjustments
to the services and job.

## Installation

```sh
npm ci
cp .env.example .env
node ace generate:key
```

Then configure `.env`:

| Variable | Purpose |
| --- | --- |
| `HOST`, `PORT`, `APP_URL` | Listening address and service URL. |
| `NODE_ENV`, `TZ`, `LOG_LEVEL` | Environment, time zone, and log level. |
| `APP_KEY` | Key generated by `node ace generate:key`. |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` | Redis connection settings; the password is optional. |
| `QUEUE_DRIVER` | Use `redis` for background jobs and scheduling. |
| `ADB_DEVICE` | Phone serial number, available through `adb devices`. |
| `ADB_APP_PACKAGE_NAME` | Android package name for mylight: `com.mylightsystems.mira` for the documented flow. |
| `MYLIGHT_EMAIL`, `MYLIGHT_PASSWORD` | Credentials required for automatic sign-in. |

The mylight credentials are optional while the Android session remains signed in.
Credential entry through ADB supports only ASCII characters without spaces or the
`%s` sequence. Each sign-in attempt starts a fifteen-minute cooldown before the
next attempt. Additional verification or an unrecognized screen requires manual
intervention.

## Development

With Redis running and the phone connected, start the server and worker together:

```sh
./bin/dev
```

This script runs the processes declared in the `concurrently` file.
To start them separately, use two terminals:

```sh
# HTTP server
npm run dev
```

```sh
# Job worker
node ace queue:work --queue=default
```

The server registers the schedule at startup. The worker must remain running to
process scheduled readings and refresh requests.

## API and job monitoring

With the default local configuration:

```sh
curl http://localhost:3333/api/battery
# {"capacity":40}

curl -X POST http://localhost:3333/api/battery/refresh
# HTTP 202: {"queued":true}
```

`GET /api/battery` returns the last stored value, or `0` if no reading has been
stored yet. The response does not include a measurement timestamp, so it cannot
distinguish a recent reading from an older value preserved after a failure.

`POST /api/battery/refresh` queues a reading. The result becomes available through
the `GET` endpoint once the job has finished.

The dashboard at `/queue-dashboard` displays job statuses and lets you retry
failed jobs or delete them. The API and dashboard routes do not have
authentication in this project; restrict access to the intended network or users.

## Useful commands

| Command | Action |
| --- | --- |
| `node ace battery:refresh` | Queues a battery reading. |
| `node ace mylight:status` | Opens mylight and reports `connected`, `disconnected`, `unknown`, or `device-unavailable`. |
| `node ace mylight:reconnect` | Attempts to sign in again when a recognized login screen is displayed. |
| `node ace adb:screenshot` | Saves a diagnostic screenshot to `tmp/screen.png`. |
| `node ace queue:scheduler:list` | Lists registered schedules. |

Commands that open an Android session close the app and put the phone to sleep
after execution. `mylight:status` returns a zero exit code only when the session
is connected.

Details about the sign-in flow and migration from older jobs are available in the
[mylight session documentation](docs/mylight-session.md) (in French).

## Project structure

| Location | Responsibility |
| --- | --- |
| `app/services/adb_service.ts` | ADB commands: gestures, app launch, and UI inspection. |
| `app/services/mylight_service.ts` | Redis locking, session lifecycle, and automatic sign-in. |
| `app/services/mylight_screen.ts` | Screen recognition and percentage extraction. |
| `app/jobs/refresh_battery.ts` | Refreshing and storing the reading. |
| `start/scheduler.ts` | Scheduling a reading every five minutes. |
| `start/routes.ts` | Battery API and dashboard routes. |
| `commands/` | Manual Ace commands. |
| `tests/` | Parser and service tests using ADB and Redis mocks. |

## Checks and deployment

```sh
npm run lint
npm run typecheck
npm run build
```

Deployment is configured in `deploy.config.ts` using Catapult: local compilation,
build upload, production dependency installation, and PM2 management of the API
and worker processes. The `.env` file and the `storage`, `logs`, and `tmp`
directories are shared across deployed releases.

Adjust the SSH host and deployment path for your environment before running:

```sh
npm run deploy
```

The remote machine also needs Redis, ADB, and access to the phone. The Catapult
tasks `battery:refresh`, `mylight:status`, `mylight:reconnect`, and
`queue:scheduler:list` run the corresponding commands on the deployed release,
for example:

```sh
npx cata task mylight:status
```
